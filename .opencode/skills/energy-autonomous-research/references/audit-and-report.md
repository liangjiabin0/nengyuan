# 审计和论文式报告

## 报告结构

固定章节顺序，与论文一致：

1. 概念与符号（来自 `evidence/` 的术语表，含出处）
2. 研究问题
3. 国内外研究现状与比较，逐条列出现有不足及其出处
4. 各方法的数学模型（`models/comparison.md` 的对照表加各方法的 `formulation.md`）
5. 候选创新方法及理论分析
6. 求解流程（各方法的 `procedure.md`）
7. 算例设置与计算环境
8. 结果、消融、边界与失败分析
9. 讨论与局限
10. 结论
11. 参考文献（学术文献与项目代码/实验附件分节）加复现附件

报告逻辑按这条链路走完。负结果、复现失败和适用边界作为研究产出写入相应章节。工作停在设计阶段时，第 5–8 章写成研究方案与待验证清单。

数字统一取自 `runs/` 的原始输出和 `analysis/` 的重算结果，口径按 `scheme-technical-report` skill 的约定（报告中的数字来自 `result.json`）。

## 算例设置与计算环境

每个正式实验记录一行：

```
case_id, data_hash, model_version, config_hash, code_commit_or_hash, seed,
command, start_time, end_time, status, raw_output
```

**输入参数**部分给出：算例来源（标准算例名或自建数据集）、规模（节点/机组/时段/样本数）、全部参数取值及其来源、负荷与出力曲线、价格与成本系数、边界条件、扰动与故障设定。转换自外部标准算例时，记录原始来源和转换过程中改动的字段。

**计算条件**部分给出：CPU 型号与核数、GPU（用到时）、内存、操作系统、语言与库版本、求解器与版本、线程数、数值精度，以及初值、容差、超时、热启动和预处理设置。

性能比较分段报告数据加载、建模、编译、求解、总耗时五列，在同硬件同精度下比较，并写明预热与重复测量规则。历史运行缺硬件信息时，该行标为 `env: unrecorded`。

## 核心审计

逐项检查并在 `audit.md` 记录结论、证据位置和处理方式：

- 术语表每条有定义与可核验出处，`本文定义` 条目已标识。
- 理论目标、算法更新式与代码逐条对应；尺度因子、正则项、裁剪、阻尼、惩罚、停止条件都在 `mapping.csv` 里。
- 用到可学习概率尺度时，核对完整似然的归一化项与尺度约束；启发式更新式的收敛性另给证明或实验证据。
- 物理指标用独立的物理方程或可信参照计算，与量测拟合残差分两行报告。
- 基线异常失败有诊断记录；所选方法与研究问题的对应关系写明。
- 每个计划内的运行都有 `success` / `failed` / `skipped` 状态和原因。统计指标写明纳入哪些输出、分母是多少。
- 主要结论能由 `runs/` 的原始数据加 `analysis/` 的脚本重算。百分比、量纲、数量级、图表与正文文字逐处对照。
- 按问题需要报告置信区间、分位数与跨场景结果。跨场景均值的差异配上离散度和检验结果后再描述其强度。
- 消融指出优势来自哪个改动；边界测试给出方法在何种条件下失效；模型复杂度增加带来的计算代价一并列出。
- 参考文献、图表、实验数据、代码版本的引用可逐条回溯。`audit.md` 里记录的检查项，以本次实际运行并留下输出的为准。

问题按影响范围定位并写进对应结论的限定语：排版问题限定在呈现层；统计审计的结论限定在统计有效性；代码可运行限定在实现层。未解决的问题在报告相应章节写明它限制了哪条结论。

审计可请 `shared-paper-peer-review` skill 的四项审计（实验支撑、可复现性、最新工作比较、理论支撑）并行过一遍，其输出归入 `audit.md`。
