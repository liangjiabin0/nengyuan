# 数学模型与求解流程说明

每个进入比较的方法（基线和候选各自一份）在 `models/<method>/` 下留三个文件：`formulation.md`（数学模型）、`procedure.md`（求解流程）、`mapping.csv`（公式—代码映射）。三轨共用这套格式，各轨的专有内容在各自的 reference 里补。

## formulation.md：数学模型

按固定顺序写，每节都出现在最终报告的方法章里：

1. **符号表。** 一行一个符号：符号、含义、类型（集合/索引/参数/决策变量/状态变量/随机变量）、域与上下界、单位、取值来源。参数的来源写文献引用键、标准号或算例文件名。
2. **假设。** 逐条编号，每条写它简化了什么、在什么条件下成立、失效时影响哪条结论。
3. **目标函数。** 给出表达式与 min/max；多目标写出权重或分层顺序及其取值依据。
4. **约束。** 按物理含义分组（功率平衡、设备容量、爬坡、储能状态转移、安全边界……），每组给出表达式、方向、索引范围、单位，并编号 `eq-<组名>-<序号>`。
5. **模型类别。** LP / MILP / QP / 锥 / NLP / MINLP，以及是否含随机、鲁棒、双层结构和凸性，附判定依据。
6. **规模。** 变量数、约束数、非零元数，按算例规模给出。

改编自文献的模型，在对应节标出原文出处（引用键 + 式号）和本文所做的改动；本文新增的部分单独标注。

## procedure.md：求解流程

同样固定顺序：

1. **总体路线。** 一段话说明从输入到解的路径，以及为什么走这条路径（对应 `formulation.md` 的模型类别）。
2. **算法步骤。** 编号伪代码，每步写清输入、操作、输出。迭代算法给出迭代变量、更新式、收敛判据。分解算法给出主问题、子问题、交互量与协调更新式。
3. **初始化。** 初值来源、预处理、变量缩放、热启动条件。
4. **参数。** 收敛容差、最大迭代次数、罚因子、步长、时间限制，各给取值与取值依据。
5. **终止与回退。** 正常终止条件；遇到不可行、无界、数值困难、超时各自的回退动作和记账方式。
6. **调用方式。** 实际使用的引擎、命令或 MCP 工具、模型文件路径，与 `experiments/` 里的运行命令对应。

流程图在报告里配一张即可，文字步骤是主件。

## mapping.csv：公式—代码映射

一行一条，列为：

```
equation_id, formulation_section, code_symbol, code_location, experiment_id, claim_id, status
```

`status` 取 `original`（原文模型）、`adapted`（改编模型）、`implemented`（本次实现并运行）、`planned`（设计中尚未实现）之一。报告里引用某条公式支撑某个结论时，按 `equation_id → claim_id` 回查这张表，`status` 为 `implemented` 的条目可用于支撑实验结论，其余条目在报告中按其实际状态描述。

尺度因子、正则项、裁剪、阻尼、惩罚、停止条件这些实现细节，同样各占一行进入映射表。

## 多方法对照表

`models/comparison.md` 用一张表并列所有参与比较的方法，列为：方法、来源（文献引用键或本文）、模型类别、目标函数形式、关键约束差异、求解算法、已实现状态、对应实验 id。这张表直接进报告的"各方法模型"一节，是"不同方法的数学模型"要求的落点。
