# 优化建模轨

## 从自然语言到结构化模型

分四步推进，每步留下可读的中间产物，后一步只依据前一步的产物工作：

1. **抽取。** 把问题描述拆成集合、索引、参数、决策变量、目标、约束六类条目，逐条写成一行自然语言加一个稳定条目 id。原文里没说清的条目标为 `pending`，攒齐后连同它各自影响哪条约束，用 `question` 工具一次问清。
2. **形式化。** 每个条目写出数学形式：变量给出域（连续/整数/二元）、上下界、单位；参数给出取值、单位、来源；约束给出表达式、方向、右端项、单位；目标给出表达式与 min/max。这一步产出 `models/<method>/formulation.md`。
3. **代码化。** 由形式化条目逐条生成 model.json 或求解代码，保留 `条目 id → 代码符号` 的对照表。一个条目对应一段代码，改模型时按 id 定位。
4. **自校验。** 运行前做静态检查，运行后做结果检查（见下文两节），检查项失败时回到对应条目 id 修改，并记录这一轮修改的原因。

模型规模变大时，把同结构约束写成按索引集合展开的一族，条目 id 带上索引范围，而不是逐条列举。

## 运行前的静态检查

逐项确认并把结论写进 `models/<method>/formulation.md`：

- 单位与量纲：等式两边同量纲；功率、电量、时间、价格的换算系数显式写出。
- 变量域：每个变量有明确的 `lb`/`ub`，整数性与实际含义一致（台数、启停用 integer/binary）。
- 约束方向：`<=` `>=` `==` 与自然语言描述逐条对照一遍。
- 系数符号：成本、收益、惩罚项的正负号与目标的 min/max 方向一致。
- 覆盖度：`pending` 条目清零，或在报告里列为已知简化。

同时判定问题类别：LP、MILP、QP、锥规划、NLP、MINLP，以及是否含随机、鲁棒、双层结构和凸性。判定不下来时标为 `unknown` 并写明卡在哪一条。求解器接受输入作为语法通过的证据；模型正确性以上述检查项和下文的结果检查为准。

## 求解路由

1. 按主 SKILL.md 的"ESOPT 与本机求解引擎"选路径：线性与整数模型经 `esopt` skill 派发 `esopt-mcp`；二次与非线性模型记录所需的 ESOPT 原生接口后，选表内本机引擎完成本次实验。
2. 同一次实验分段记录建模、转换、求解、后处理各段时间，写进 `runs/`。
3. 采用线性化、松弛、分解或近似时，记录变换式、成立条件与误差界，并把解代回原问题算残差与违反量，两个问题的最优值分列。
4. 每次求解留下：调用命令、model.json 或模型文件、原始 JSON 输出、`termination_status`、耗时、求解器与版本。

## 结果的独立检查

用原始变量取值和原始输入重算一遍，逐项记录：

- 目标值：按 `formulation.md` 的目标表达式重算，与求解器返回值比对。
- 可行性：等式残差、不等式违反量、变量边界违反量，各给最大值和违反条目数。
- 整数问题：整数可行性、最优界、gap、时间限制、终止状态。
- 连续非线性问题：在正则条件成立处检查 KKT 残差与可行性，换若干组初值重跑，把得到的解标为局部驻点；全局性主张另附凸性证明、对偶界或全局求解器结果。

交叉核验用三种来源之一：解析解、小规模穷举、与建模路径独立的第二套实现（如 `esopt_compare_reference` 的 HiGHS 对照）。

按状态分账记录：不可行、无界、数值困难、超时有解、超时无解。求解器返回的 `success` 记为求解状态，研究任务是否成功另按 `protocol.md` 的验收指标判定，两者在报告中分列。

## 创新方向与数值方法选择

把"更准"拆成四项分别测量：模型保真度（与物理/实测的偏差）、参数估计误差、可行性（对真实约束的违反率）、优化精度（gap 或 KKT 残差）。把"更快"拆成五项：迭代次数、单步成本、总墙钟时间、内存峰值、成功率。

**考虑更多边界约束时**，在同一真实约束集合下评估所有方法：把新增约束同时加进基线，比较违约率、目标值和计算代价三列。约束集合不同的两组结果，在报告里分表呈现并注明各自的可行域。

**抗差性**按来源分四组独立测试，各出一张表：

| 组 | 注入方式 | 指标 |
|---|---|---|
| 量测异常 | 噪声、野值、缺失 | 估计偏差、可行性保持率 |
| 参数偏差 | 阻抗、成本、容量扰动 | 目标值漂移、违约率 |
| 拓扑与模式错误 | 开断状态、控制模式错配 | 检出率、降级后的可用解比例 |
| 输入解析错误 | 自然语言约束歧义、单位错、类型错 | 静态检查检出率、修复轮次 |

四组指标分别报告，各自对应不同的改进机制。

**数值方法选择**按问题性质先筛候选：光滑性、凸性、稀疏性、条件数、导数可得性、问题规模，每项写出它排除了哪些方法。再在目标问题上用相同的精度与可行性判据做对照实验，报告收敛曲线、达到同一精度所需时间和成功率。方法优劣的结论限定在本次测试的问题类别与规模范围内；文献中的收敛阶作为候选筛选依据，最终排序以本次实验数据为准。

调研数值方法时纳入数值分析、应用数学、优化与统计期刊，每篇记录它给出的收敛条件和适用问题类，与本问题的性质逐条对照后再选用。
