# 国网总部科技项目指南编制

按证据顺序工作：先确定范围和范例基线，再完整阅读资料、形成综述和课题设计，最后写指南。不得从模型常识补造术语、方法、系统名称、工程事实或验收阈值。

## 必读资源

开始任务后，完整读取下列文件：

- `references/reusable-constraints.md`：永久适用的内容、边界和禁则。
- `references/writing-style-and-examples.md`：七段体例、各部分写法、正反样例。
- `references/evidence-and-terminology.md`：全文阅读、术语、指标和证据规则。
- `references/source-extraction-and-web-supplement.md`：论文、专利、标准分类提取，PDF质量升级，网络补证和标准版本核验规则。
- `references/dense-single-document-summary.md`：面向技术人员的高密度单篇摘要结构、信息排序、公式门禁和生产输出禁则。
- `references/evidence-system-and-incremental-build.md`：原子证据、资料准入评分、缺口搜索、三类映射、标准/专利监测、指标卡、分层成果和增量构建规则。
- `references/workflow-and-deliverables.md`：目录、阶段门槛和成果清单。
- `references/fixed-guide-format.md`：指南建议稿固定版式、内容骨架、母版和生成方法。
- `references/qa-checklist.md`：最终门禁和渲染检查。

同时使用 `doc`、`pdf`、`spreadsheets` 技能处理对应文件，并遵守其渲染和完整性检查要求。

## 强制工作流

1. **确认输入和范围。** 扫描工作区，不预设课题数。每个课题以用户提供的“个人研究方向/研究范围/撰写指引”等文件为最高优先级边界。缺失时可清点和总结资料，但不得代拟正式课题指南。
2. **建立当次范例基线。** 扫描“国网范例”或用户指定目录，按封面/正式发布日期确定最新范例，不按文件修改时间猜测。运行 `scripts/analyze_guide_examples.py` 辅助提取全文、七段结构和相关项目；人工完整阅读最新范例中与本项目相近的项目，并用前一批次交叉核对。输出《最新范例写作基线与重复边界》。不得跳过此步，也不得把本 Skill 内的 2026 样例永久当作最新口径。
3. **处理旧稿但不依赖旧稿。** 若有旧稿、标黄、批注或修订，逐项吸收到当次约束和修改对照中，清稿时全部删除。若无旧稿，直接按本 Skill 的永久规则执行；不得要求虚构“V2问题清单”。
4. **资料清点、分类和去重。** 为全部文件分配资料 ID，计算 SHA-256。只有哈希完全一致才算完全重复。同一资料可归入多个课题，但只维护一份唯一主记录和主总结，再按课题复制引用。记录页数、文种、全部所属课题、提取质量、阅读状态和输出路径。
5. **按文种完整阅读和单篇总结。** 完整执行 `references/source-extraction-and-web-supplement.md` 和 `references/dense-single-document-summary.md`。论文按理论、方法、算例、贡献与局限提取；专利按独立权利要求和保护组合提取；标准按适用对象、测试族、边界、数值、判定与版本提取；目录/索引文件只总结其检索范围、收录结构和可用边界。PDF文本层不足、双栏错序、乱码、公式或表格错配时，依次升级到版面解析、全页渲染、OCR或AI视觉核验。未达到 `FULLY_READ` 与 `SUMMARY_COMPLETE` 的资料不得支撑正式结论；`BLOCKED` 或 `NEEDS_OCR_OR_AI_REVIEW` 不得同时标为 `SUMMARY_COMPLETE`。每份资料保留后台证据记录和一份独立高密度 Markdown；正式汇编从高密度 Markdown 生成，不把 Evidence ID、Gold/Silver/Insight、Quality Gate、OCR 日志等后台字段写入人读正文。
   批处理必须同时运行 `scripts/check_dense_summaries.py` 与 `scripts/check_summary_semantics.py`；结构门禁通过但正文仍含英文摘要、页眉图注、OCR/翻译碎片或空泛段落时，仍视为失败。网络翻译返回原文、验证码或异常页面时不得缓存为成功结果。
6. **主动联网补证和标准换版检查。** 对全部标准、专利和正式结论所依赖的关键论文执行网络核验。标准逐项查询主管机构或全国标准信息公共服务平台，记录当前版本、新版本、替代方式、发布日期、实施日期、核对日期和官方链接；新版已发布时区分“已实施替代”和“尚未实施”。同时判断指南是否缺少理论、工程示范、测试验收、指标、知识产权、中国/国网适用性或反证资料，候选网络资料使用 `NET-xxx` 独立编号，不与本地原文混写。
7. **建立结构化证据系统。** 完整执行 `references/evidence-system-and-incremental-build.md`。以结构化数据为唯一事实源，为资料评分并形成原子证据；按课题计算六类证据覆盖度，用缺口驱动 NET 搜索；建立论文—专利—标准映射、标准依赖监测、专利权利要求特征矩阵、工程矛盾—研究空白—项目增量表和指标卡。Markdown、DOCX、XLSX 均从结构化数据派生。
8. **先综述后设计。** 全部非重复资料完成后，依次形成单课题综述、专利拥挤区、标准适用边界、研究空白和三个递进研究点。总研究综述必须按课题收录全部唯一资料的一页式单篇总结；详细总结与一页版通过资料 ID 一一对应。
9. **术语和工程边界门禁。** 核心术语分为 N/A/D/P/X 级。标题、关键技术和指标只允许 N/A 级核心术语。通用信息技术只能作为解决具体电力系统对象、变量、状态、规划、运行、控制或试验问题的支撑工具。
10. **先课题、后总体。** 先写各课题设计说明和独立指南部分，明确输入、方法、输出、验证及课题间传递关系；再合成项目的应用场景、功能需求、关键技术和完整指南。功能需求、关键技术与课题必须按相同顺序一一对应。每个课题固定写成“课题标题 + 一段预期目标 + 三段考核指标”，预期目标按“机理/模型 -> 核心方法 -> 工具/方案/验证”三步递进，三段指标依次为“核心成果与性能、验证对象与场景、成果产出”。
11. **指标需可验收。** 先形成指标卡，明确验收对象、公式/统计口径、分子分母、测试系统、场景、数据、基线、阈值依据、失败判定、适用边界和证据 ID。文献算例结果不得直接转为项目指标；证据不足时写成果型指标或标注“建议值，需在可研或预试验中标定”。
12. **使用固定母版并逐页检查。** 指南建议稿必须以 `assets/sgcc-guide-fixed-template.docx` 为母版，优先用 `scripts/build_fixed_guide.py` 从结构化 JSON 生成；不得从空白 DOCX 重建，不得使用表格承载指标。按实际课题数自动增删课题块，保留封面、目录、指南组页、页眉页脚、页码、样式、分节和非技术字段。更新目录并渲染 DOCX/PDF，逐页检查；检查 XLSX 结构、公式和打开完整性。使用 `scripts/check_guide_docx.py` 做固定版式、七段结构、课题块、标黄、批注、修订、禁用词和标题一致性静态检查。只有用户明确提供更新的正式公司模板并要求替换时，才可更新本 Skill 母版；不得在单次任务中临时改用其他版式。
13. **分层、增量交付。** 同时输出决策版综述、全部一页总结汇编和详细证据附件；保存输入哈希、标准/网络核验日期、缓存命中和变更影响。只有 `references/qa-checklist.md` 全部通过才能宣称完成。资料、范围、权限或工程数据不足时保存中间成果，报告准确完成度和断点，不生成虚假终稿。

## 核心写作顺序

```text
最新范例基线与重复边界
  -> 课题范围与资料总清单
  -> 分类全文阅读、PDF升级与高密度单篇总结
  -> 网络补证与标准版本核验
  -> 原子证据、准入评分、覆盖缺口和三类映射
  -> 工程矛盾、研究空白、项目增量和指标卡
  -> 单课题综述与术语校核
  -> 三点式课题设计
  -> 单课题指南与证据映射
  -> 跨课题冲突消解
  -> 总指南及决策版/一页版/详细证据分层成果
  -> 逐页渲染和结构质检
```

应用场景写“背景事实 -> 既有做法 -> 具体矛盾及工程后果 -> 应用对象”；功能需求写业务能力，不提前塞入算法；关键技术按课题顺序写对象和研究动作；每个课题写“机理/模型 -> 核心方法 -> 工具/方案/验证”；成熟度按成果分别给出攻关前后等级和验证环境。

## 固定建议稿输出

1. 完整读取 `references/fixed-guide-format.md`，不得只按截图或旧稿猜测格式。
2. 将指南内容整理为 `scripts/build_fixed_guide.py` 规定的 JSON；功能需求项数、关键技术项数和课题数必须相等。
3. 用固定母版生成 DOCX。课题数量可以变化，但每个课题始终占 5 个连续段落：标题、预期目标、指标（1）、指标（2）、指标（3）。
4. 用 Word 或 LibreOffice 重新分页、更新域并导出 PDF。目录正文项目页默认从第 2 页开始；若项目标题前新增内容导致页码变化，必须据实际页码更新目录。
5. 运行 `scripts/check_guide_docx.py`。任何固定格式错误均必须修复，不能降级为普通警告。
6. 逐页检查封面、目录、指南组页、项目标题、课题标题及其后续段落、页码和末页；DOCX 与 PDF 同时交付。

## 停止条件

出现下列任一情形时，不得输出正式终稿：

- 课题缺少用户确认的范围依据；
- 正式结论所用资料未完整阅读或无页码/条款定位；
- 标题或指标含 P/X 级核心术语；
- 指标阈值无依据且未标为待标定；
- 跨课题研究对象、方法或成果接口存在未解决冲突；
- 最新范例未读取，或 DOCX/XLSX 未完成渲染与完整性检查；
- 指南建议稿未使用固定母版、含 Word 表格、课题块结构不符合规定，或固定格式检查未通过。
