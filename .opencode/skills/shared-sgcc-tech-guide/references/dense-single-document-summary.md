# 高密度单篇技术摘要

## 1. 定位与输出

每份唯一源文件生成一份独立 Markdown。后台继续保留完整题录、页码/条款、证据等级、解析状态和质量门禁；面向技术人员的生产摘要只保留经过核实的高价值技术内容，不展示数据库、OCR、审计或调试字段。

题名必须从正文首页、题录页、权利要求书或标准封面解析。外文题名译为中文，并在需要消歧时于正文保留原文题名。不得用文件名充当题名，不得用省略号、字段名或“从文本中稳定识别”等占位语补齐缺失内容。

生产摘要固定为：

```markdown
# 正式中文题名

> **核心结论：** 1—3句，直接说明技术机制、主要结果或规范价值。

## 1. 文种专项标题
...

## 5. 文种专项标题
...
```

标题后立即给出核心结论，正文恰有 5 个二级章节，不再追加“一句话总结”。常规资料控制在 1500—2500 个中文字符；复杂且高价值的资料可放宽至约 3000 字。信息按“技术重要性 × 对理解机制的贡献 × 对技术判断的贡献”排序，不按原文目录或抽取顺序平均压缩。

## 2. 论文

五段结构：

1. 研究问题与总体思路；
2. 核心理论与方法；
3. 技术实现流程；
4. 实验与关键结果；
5. 核心创新与局限。

优先保留研究对象和边界、模型假设、输入输出、关键变量与约束、方法机制、与基线的本质差异、数据/算例规模、评价指标、作者直接报告的关键数值、适用条件及未验证范围。摘要应说明“为何有效”，不能只列方法名。

作者声明与摘要者综合判断必须区分。论文算例仅能证明相应对象、工况、基线和指标下的结果，不能直接转成国网项目验收阈值。

任何自行计算的倍数、百分比或提升幅度先分类：

- `Exact Comparable`：实验条件和统计口径一致，可给明确结果；
- `Approximate Comparable`：口径有差异，只能写“粗略折算”“约若干数量级”；
- `Non-Comparable`：条件差异过大，不计算倍数。

优先写作者直接报告的数据，不用摘要器衍生指标挤占篇幅。

## 3. 专利

五段结构：

1. 要解决的技术问题；
2. 核心技术方案；
3. 关键技术机制；
4. 权利要求与保护核心；
5. 技术效果与局限。

保护结论以独立权利要求为主，逐项还原必要技术特征及其组合关系；从属权利要求用于说明进一步限定。实施例、摘要和背景只能帮助理解，不能改写保护边界。明确区分权利要求必要特征、可选实施方式和算例配置。

涉及多种“优化”时，必须澄清电力系统优化、机器学习超参数优化、模型训练与在线推理各自的输入、输出和作用，不能把超参数搜索写成直接求解电网优化。技术效果分成“机制上可预期”与“实施例已定量验证”；缺少时延、网损、电压、误差或寿命对比时，明确尚不能转化为确定性能增益。

## 4. 标准

五段结构：

1. 适用范围与检测/约束对象；
2. 核心技术要求；
3. 主要检测项目与方法；
4. 关键参数与判定；
5. 抽样、复检与记录。

围绕“如何试、在什么边界下试、用什么设备试、如何判定、何时复检”组织内容。参数按技术决策价值排序：

- `P0-A`：直接决定合格/验收的阈值或判据；
- `P0-B`：试验有效性的边界，如电压、功率、时间、点数、短路容量、X/R；
- `P0-C`：仪器准确度、响应时间、带宽、采样能力等关键设备能力；
- `P1`：直接影响结果计算的统计规则；
- `P2`：普通记录字段，通常不进入摘要。

使用“测试族—关键条件/参数”三线表聚合同一测试的边界、设备、统计和判定，不把每个数字拆成独立字段。按技术风险、试验复杂度、参数密度和判定重要性分配篇幅，不在各章节间平均分配。保留标准原文的“应、不得、不应、宜、可”，数值必须同时保留对象、单位、适用条件和条款语境。引用外部标准但未取得正文时只说明依赖关系，不移植其限值。

标准版本状态必须在后台经官方来源核验。新版已发布但未实施时，同时说明旧版当前有效和切换日期；项目周期跨越切换日期时，新版全文和差异表是指南编制输入。

## 5. 目录、索引和清单

五段结构：

1. 文件性质与收录范围；
2. 分类结构与检索入口；
3. 与本项目直接相关的条目；
4. 可提供的线索与不可提供的证据；
5. 后续取全文和核验要求。

目录或索引不得伪装成论文、标准正文或工程证据。它只能证明条目存在、分类关系或检索线索；未取得被索引文件全文时，不得据题名推断方法、结论、限值或法律状态。内容不足时允许短于常规篇幅，但必须具体说明其实际信息价值。

## 6. 公式可靠性门禁

LaTeX 语法正确不等于与原文一致。每个拟进入摘要的公式必须同时通过：原始页面定位、原生数学抽取或必要的公式 OCR/视觉恢复、LaTeX 规范化、语法检查、源级结构检查和上下文变量检查。

源级检查至少覆盖：min/max 层级、上下界、上下标、求和、分式、矩阵、转置、范数、不等号、正负号、括号范围、约束归属和变量定义，特别复核 `p_0^- / p_0^+`、`min / max`、`\sum`、`\le / \ge`、`\mathbf 1^{\mathsf T}`、`\mathbf 0^{\mathsf T}` 等 OCR 易错结构。

只选择 2—5 个定义核心模型、算法机制、目标函数或主要约束且不可用自然语言替代的公式。完整结构不能可靠确认时，只输出已确认的局部关系；局部也不能确认时不输出公式，改用自然语言解释功能。少一个公式优于保留错误公式。

## 7. 网络补充与生产边界

网络资料先使用 `NET-xxx` 建独立记录，注明网络来源、核对日期、全文状态和可点击链接。取得并完整核读后，可按同一文种模板生成独立摘要并进入综述；未取得全文的候选只能进入补证清单。不得把网络材料内容混写成某份本地资料的原文结论。

生产 Markdown 禁止出现 Evidence ID、Gold/Silver/Insight、SOURCE/INFERENCE、Quality Gate、Coverage Manifest、OCR Provenance、解析器名称、内部 JSON 字段或“重新核对原 PDF”等过程性措辞。这些内容留在后台台账。生产摘要可以自然说明资料本身的验证不足、适用边界或尚未给出定量结果。

## 8. 自动门禁

批量生成后连续运行双门禁：

1. `scripts/check_dense_summaries.py` 检查一源一 Markdown、正式题名、核心结论位置、恰好 5 个二级章节、文种标题匹配、字符密度、禁用占位词和后台字段泄漏、公式语法、公式源级审核状态、数值单位/适用条件、专利 Claim 与实施例分离、标准 P0 信息优先级、网络来源链接和版本核对日期；
2. `scripts/check_summary_semantics.py` 检查核心结论是否为中文技术结论、每段是否有实质信息、是否残留英文摘要、页眉页脚、整段图注、参考文献、OCR/翻译碎片或后台字段。

任一门禁失败均不得标记 `SUMMARY_COMPLETE` 或进入正式汇编。禁止把摘要首句、结论首句、关键词命中片段或机器翻译原样拼接作为核心结论。英文资料须先形成连贯中文技术复述；网络翻译失败、返回原文或触发验证码时，不得缓存为成功翻译，改用本地已核中文摘要、AI按源文阅读提炼，或标记受限摘要。
