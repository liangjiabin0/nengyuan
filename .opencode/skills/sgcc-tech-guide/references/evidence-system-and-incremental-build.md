# 结构化证据系统与增量构建

## 1. 唯一事实源

使用结构化 JSON/JSONL 保存资料、证据、覆盖度、标准、专利、指标和构建状态。Markdown、DOCX 和 XLSX 是派生视图，不得在派生文件中形成无法回写结构化记录的新结论。

## 2. 原子证据

每条原子证据只支撑一个明确判断，至少包含：证据 ID、资料 ID、证据类型、原文、中文表达、页码/条款/权利要求定位、来源属性、证据强度、可支撑内容、不可外推内容、所属课题和核验状态。

证据 ID 使用 `EV-资料ID-三位序号`。来源属性只能使用原文证据、OCR核验、AI视觉核验、官方网络核验、第三方网络核验和综合归纳。综合归纳必须引用至少一条非综合证据，不能循环引用。

## 3. 资料准入评分

按八维 0—5 分评分：来源权威性、范围相关度、理论/工程贡献、证据可定位性、时效性、中国/国网适用性、可验证/可复现性、与其他证据一致性。总分 40：A 为 32—40，B 为 24—31，C 为 16—23，D 为 0—15。

正式指南核心表述至少需要一项 A 级直接证据，或两项相互独立的 B 级证据，并通过标准与专利边界检查。评分理由和缺陷必须记录，不能只输出等级。

## 4. 证据缺口驱动搜索

每个课题检查六类覆盖：核心理论与模型、方法和算法、工程应用或示范、标准及测试验收、专利保护与路线拥挤度、局限反证和失效条件。每类按 0 缺失、1 部分、2 充分评分。

低于 2 的类别生成 `NET-xxx` 搜索任务，记录查询意图、建议权威来源、拟支撑内容、全文状态、核验日期和链接。取得全文后按资料类型进入相同阅读和总结流程；未取得全文只保留候选，不得写成已核结论。

## 5. 论文—专利—标准映射

按技术特征同时记录论文理论/方法、专利核心保护、标准适用/测试边界和指南使用结论。论文不证明自由实施，专利不证明工程性能，标准最低要求不等于创新指标。映射必须指出证据缺口、保护拥挤区、可创新区和不可使用表述。

## 6. 标准依赖与版本监测

标准版本监测保存上次和本次核验日期、当前状态、新标准、替代方式、发布/实施日期、官方链接、状态变化、项目周期影响和使用结论。项目实施或验收跨换版日时，必须取得新版全文或列为最高优先级待补证。

从可靠正文提取规范性引用标准，形成标准依赖链并检查联动换版。引用表无法可靠识别时明确记录缺口，不从 OCR 乱码推断标准号或替代关系。

## 7. 权利要求特征矩阵

专利以独立权利要求为核心，形成权利要求特征矩阵，至少列出专利号、权利要求号、必要技术特征、输入、处理、输出、装置/模块、核心保护组合、相近专利、拥挤区、规避方向、同族/法律状态和 FTO 待核项。第三方状态只作导航。

## 8. 工程矛盾—研究空白—项目增量

从综述到指南之间必须形成三张中间表：

1. 工程矛盾：对象、工况、现有做法、具体问题、工程后果和证据 ID；
2. 研究空白：已有理论/工程/标准/专利覆盖、未解决内容、不能解决的原因和证据 ID；
3. 项目增量：拟新增模型、方法、工具/方案、验证、上下游接口、差异化和证据 ID。

三张表逻辑一致后才能进入项目名、关键技术和课题设计。

## 9. 指标卡

每个正式指标先建立指标卡：课题、指标类别、验收对象、定义、公式、分子分母、有效样本、测试系统、场景、数据、基线、阈值来源、成功条件、失败判定、适用范围、证据 ID 和标定状态。字段不完整时改为成果型指标或明确可研/预试验标定。

## 10. 分层正式成果

同时输出：决策版研究综述、全部一页总结汇编、详细证据附件、固定格式国网指南和证据系统工作簿。决策版不堆积单篇全文；一页汇编只压缩已核详细总结；详细附件保留原子证据、条款、权利要求、OCR和网络核验。

## 11. 增量构建

构建清单记录输入文件 SHA-256、总结哈希、标准/网络核验日期、缓存命中、变化资源、受影响课题和派生成果。输入未变化时复用全文提取、OCR、翻译和题录缓存；发生变化时仅重建受影响的证据、覆盖度、课题综述和正式成果。首次构建标记为全量基线。

## 12. 门禁

不得出现无资料来源的原子证据、只有等级无理由的准入评分、缺口为 0 但没有 NET 任务、标准状态无官方链接、专利保护只取摘要、指标卡字段缺失却写入数值阈值、派生文档与结构化事实源不一致或构建清单未记录输入变化。
