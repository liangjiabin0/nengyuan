# 国网指南建议稿固定格式

本文件规定 `sgcc-tech-guide` 输出指南建议稿时必须使用的 Word 版式与内容骨架。固定的是版式、层级和课题块结构；项目名称、指南组、课题数量、技术内容、期限、经费和牵头单位以当次证据为准。

## 1. 固定资源

- 母版：`assets/sgcc-guide-fixed-template.docx`
- 生成脚本：`scripts/build_fixed_guide.py`
- 校验脚本：`scripts/check_guide_docx.py`

不得从空白文档重建指南建议稿。不得把研究大纲、编制说明、证据说明、指标口径表或彩色编辑标题放入正式指南正文。

## 2. 页面与分节

- A4 纵向，3 个分节：封面、目录、正文。
- 页边距：上 2.80 cm、下 2.50 cm、左 2.80 cm、右 2.60 cm。
- 页眉距 1.50 cm，页脚距 1.60 cm。
- 封面不显示页码；目录使用罗马页码；正文指南组页从阿拉伯数字 1 开始。
- 正文先设独立指南组页，下一页开始项目正文。
- 正文不得使用 Word 表格；考核指标必须使用连续段落。

## 3. 固定视觉样式

| 对象 | 中文字体 | 字号 | 对齐及段落 |
|---|---|---:|---|
| `附件2` | 黑体 | 16 pt | 左对齐，固定 28 pt 行距 |
| 封面两行主标题 | 华文中宋 | 22 pt | 居中，固定 34 pt 行距 |
| 封面日期 | 仿宋_GB2312 | 16 pt | 居中，固定 28 pt 行距 |
| `目    录` | 黑体 | 20 pt | 居中 |
| 目录指南组 | 黑体 | 15 pt | 两端对齐，保留点线和页码 |
| 目录项目名 | 宋体 | 14 pt | 左缩进，保留点线和页码 |
| 正文指南组 | 黑体 | 22 pt | 单独一页，居中 |
| 项目标题 | 黑体 | 18 pt、加粗 | 居中，允许按中文词组自然换行 |
| 七个一级标题 | 黑体 | 16 pt | 两端对齐，段前 8 pt，与后文同页 |
| 课题标题 | 黑体 | 16 pt | 两端对齐，与后续预期目标同页 |
| 正文 | 仿宋_GB2312 | 16 pt | 两端对齐，固定 28 pt 行距，首行缩进 2 字符 |
| 正文标签 | 仿宋_GB2312 | 16 pt、加粗 | `应用场景：`、`功能需求：`、`关键技术：`、`预期目标：`、`考核指标：`仅标签加粗 |

所有英文、拉丁字母和阿拉伯数字使用 Times New Roman。不得出现彩色文字、底纹、标黄、批注或修订。

## 4. 固定内容骨架

```text
封面
目录
指南组页
项目标题
一、学科、根技术
二、应用场景、功能需求及关键技术
  规划对应关系
  应用场景：背景事实 -> 既有做法 -> 具体矛盾及工程后果 -> 应用对象
  功能需求：按课题顺序列“一是、二是、三是……”
  关键技术：按相同顺序列“一是、二是、三是……”并说明课题传递关系
三、课题内容
  课题1：...
  预期目标：针对...，一是...；二是...；三是...。
  考核指标：（1）核心成果与性能
  （2）验证对象、规模、场景、基线、统计口径和失败判定
  （3）报告、知识产权、论文、软件著作权或标准等成果产出
  ...按实际课题数重复同一 5 段课题块
四、技术成熟度及成果应用
五、项目实施期限
六、支持经费限额
七、牵头单位
```

## 5. 对应关系

- 功能需求项数 = 关键技术项数 = 课题数。
- 三者顺序必须一致，不得出现无课题承接的需求或关键技术。
- 每个课题预期目标必须有且只有三个肉眼可辨的递进研究点：机理/模型、核心方法、工具/方案/验证。
- 每个课题固定三段考核指标，禁止增加“主要研究内容”“预期成果”“知识产权与论文”等平行小标题。
- 指标详细口径同时写入证据台账；正式指南第（2）段保留足以验收的测试系统、场景、基线和统计口径，不使用表格。

## 6. 生成输入

`scripts/build_fixed_guide.py` 接收 UTF-8 JSON。核心字段如下：

```json
{
  "guide_year": 2027,
  "cover_date": "2026年8月",
  "guide_group": "某指南组",
  "project_number": 1,
  "project_name": "项目名称",
  "discipline_root_technology": "电气工程-电力系统及其自动化（某根技术）。",
  "plan_alignment": "建议对应……相关技术方向。",
  "application_scenario": "……",
  "functional_requirements": ["……", "……"],
  "key_technologies": ["……", "……"],
  "technical_route": "技术路线按照……递进展开。",
  "topics": [
    {
      "title": "课题名称",
      "problem": "具体问题",
      "research_points": ["分析并建立……", "研究并提出……", "形成或研发……"],
      "interface": "为下一课题提供……",
      "metrics": {
        "performance": "形成……，达到……",
        "validation": "在……开展验证……",
        "outputs": "提交……，申请……"
      }
    }
  ],
  "maturity_and_application": "……",
  "duration": "……",
  "budget_limit": "待核定。",
  "lead_unit": "待核定。"
}
```

脚本会拒绝功能需求、关键技术和课题数量不一致，拒绝每课题不是三个研究点，拒绝缺少三类指标。

## 7. 最终检查

1. 用 Word 或 LibreOffice 更新域、重新分页并导出 PDF。
2. 运行 `check_guide_docx.py`，确保固定版式、七段结构和全部课题块通过。
3. 逐页检查封面、目录、指南组页、项目标题、课题标题与后续正文、页码、末页及目录页码。
4. 仅当 DOCX、PDF 和静态检查均通过时交付。
