# 统一流程与成果组织

本文件规定能元国网指南任务的目录、阶段门槛和成果清单。运行环境是隔离工作目录；**全部成果必须写在本次任务子文件夹内**。

## 1. 工作目录与任务子文件夹

```text
<隔离工作目录>/
├── INDEX.md                          # 系统生成，只读
├── TASK.md                           # 系统生成：构想、建议任务名、附件索引
├── literature/                       # 用户附件 Markdown，只读
├── refs/                             # Skill 参考副本，只读
└── <任务名>/                         # Agent 创建，唯一成果根
    ├── 00_项目总体/
    │   ├── 01_输入与范围
    │   ├── 02_最新范例基线与重复边界
    │   ├── 03_资料总清单与阅读日志
    │   ├── 04_结构化证据系统/
    │   ├── 05_三类证据与研究设计/
    │   ├── 06_总成果渲染与检查
    │   └── 07_唯一资料主总结与网络补充/
    │       ├── 01_详细版
    │       ├── 01_高密度单篇总结_V7
    │       └── 02_一页版
    ├── 01_课题1_实际名称/
    │   ├── 00_范围依据
    │   ├── 02_单篇资料总结_详细版
    │   ├── 03_单篇资料总结_一页版
    │   ├── 03_单篇资料总结_高密度V7
    │   ├── 04_单课题综述
    │   ├── 05_课题设计说明
    │   ├── 06_单课题指南
    │   ├── 07_证据映射
    │   └── 08_渲染与检查
    ├── 02_课题2_实际名称/
    └── 05_正式成果/
```

约束：

- 先创建 `<任务名>`，再写任何课题或总体文件。
- 任务名来自 `TASK.md` 的建议任务名，或清洗后的正式项目短名。
- 不得在工作目录根、`literature/`、`refs/`、`knowledge-corpus/` 写入成果。
- 不得生成 V6 历史副本、`page-*.png`、contact sheet。必须按 `v7-required-deliverables.md` 一次性逐一落盘。
- 每完成一阶段立刻落盘，便于界面刷新文件树。

`05_三类证据与研究设计` 至少包含：

中间成果必须归入对应总体/课题目录；不得用平铺副本替代课题归档。

## 2. 阶段流程

### 阶段 A：启动与基线

1. 读取 `TASK.md`、`INDEX.md`、`literature/`。
2. 创建任务子文件夹，写出范围与课题草案（可先按 3—5 个递进课题占位，随后用证据校正）。
3. 用 `refs/` 体例 + 知识库相近项目建立写作基线和重复边界。
4. 有旧稿时提取批注/标黄/修订；无则跳过。

### 阶段 B：证据处理

1. 建立资料清单、去重和阅读日志。
2. 按论文、专利、标准、指南/工程资料分类提取；同一资料一份主记录。
3. 对实际可读资料写详细总结和一页版；按课题复制引用，不复制无关全文。
4. 联网核验关键标准/专利/公开技术；标准形成版本检查。
5. 建立原子证据、准入评分、六类覆盖矩阵；缺口生成 NET 任务。
6. 完成三类映射、标准监测、专利特征矩阵、工程矛盾—研究空白—项目增量和指标卡。

### 阶段 C：课题研究设计

1. 在该课题已有证据上形成单课题综述。
2. 明确研究什么、不研究什么、与其他课题接口及与已有成果差异。
3. 设计三个递进研究点，绑定证据、输入、方法、输出和验证。
4. 形成单课题指南与指标卡。

### 阶段 D：综合与成稿

1. 检查跨课题冲突。
2. 生成至少 3 个项目名候选后选定一个。
3. 合成应用场景、功能需求、关键技术和课题内容；三者顺序一一对应。
4. 按 `fixed-guide-format.md` 写入 `05_正式成果/guide.json`。
5. 能运行时用 `scripts/build_fixed_guide.py` 和固定母版生成 DOCX。
6. 写决策版综述、一页总结汇编和详细证据。

### 阶段 E：质检与交付

1. 清除标黄、批注、修订、编辑括号、占位符。
2. 能运行 `check_guide_docx.py` 则运行。
3. PDF / LibreOffice / 逐页渲染尽力而为，失败不撤回已落盘的 JSON 与 Markdown。
4. 公开回复只报告任务文件夹、课题数、关键路径和未完成项。

## 3. 建议成果包

正式成果放在 `05_正式成果/`，不要使用 V6 文件名：

- 指南建议稿（`guide.json`，以及可生成的 DOCX）
- 决策版研究综述
- 详细证据附件或一页总结汇编
- 证据系统与指南编制台账
- 编制说明与质量检查报告
- 待补证清单（有缺口时）

中间成果至少包括资料总清单、阅读日志、详细/一页单篇总结、单课题综述、课题设计说明、单课题指南、证据映射、跨课题冲突消解和质量报告。

## 4. 断点与完成度

断点记录最后处理的资料 ID、下一位置、问题和输出路径。最终回复报告实际课题数、资料总数/唯一数、完整阅读数、总结数、质量门槛结果、任务文件夹路径和未解决问题。
