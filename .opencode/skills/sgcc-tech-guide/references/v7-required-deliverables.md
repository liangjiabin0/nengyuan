# V7 必须成果清单

本文件规定能元一次生成必须落盘的 V7 成果。对照样例是「四课题高价值高可靠全量版」的**产品层**，不是压缩包里的全部 3700+ 工作底稿。

## 1. 必须生成

目录均写在 `./<任务名>/` 内。资料份数按当次实际命中的唯一资料计，不要求凑满 123 篇；但每份唯一资料都必须同时有详细版、高密度 V7、一页版，且资料 ID 一致。

高密度总结体例见 `dense-single-document-summary.md`：正式中文题名、核心结论、恰好 5 个文种专章。一页版保留题录、准入、方法、结果、贡献、局限和 NET 候选。

## 2. 宿主派生（保持可修改）

Agent 写好 Markdown / JSON 后，宿主会生成可编辑派生，不必手写空白 DOCX：

- `指南建议稿.docx`（固定母版 + `guide.json`）
- `决策版研究综述.docx`
- `单篇资料高密度总结汇编.docx`
- `一页总结汇编.docx`
- `详细证据附件.docx`
- `编制说明与质量检查报告.docx`
- `证据系统与指南编制台账.xlsx`（资料总清单 / 标准版本监测 / 网络补证 / 研究设计 / 指标卡）
- 各课题综述、设计说明、指南条目、证据映射的 DOCX
- 课题目录中的唯一总结副本（与主记录正文一致）

这些派生必须能用 Word / Excel 打开再改。Markdown 与 JSON 仍是可回写的事实源。

## 3. 明确不要生成

压缩包里的下列内容是工作底稿或历史副本，**禁止**写入任务文件夹：

- 任何 V6 文件名、`00_V6来源说明`、`09_V6结构化证据`
- `page-*.png`、contact sheet、xlsx_preview、渲染终版/空白/重建目录
- `.inspect.ndjson`、提取对照调试 JSON
- 把 OCR 全文再复制一份到每个课题的 `01_全文提取/`（全文只保留在 `00_项目总体/07_唯一资料主总结与网络补充/01_全文提取/` 或 `literature/extracted/`）
- 平行的「终版2」「空白2」多版本

PDF 与逐页渲染尽力而为，不作为完成门禁。

## 4. 对应关系（必须同时成立）

- `guide.json` 中功能需求项数 = 关键技术项数 = 课题数 = 课题文件夹数
- 每个课题预期目标只有三个递进研究点；考核指标固定三段
- `resources.json` 的资料 ID 与三类唯一总结文件名一致
- 课题证据映射中的资料 ID 必须能在唯一主总结中找到
- `guide_reasoning.json`、指标卡、单课题指南、总指南同一套矛盾—空白—增量
- 派生 DOCX / XLSX 不得写出源文件没有的新结论

## 5. 一次性落盘规则

1. 先建任务文件夹并写范围说明。
2. 按工作流阶段**逐一**写文件，写完一类立刻落盘，不要等最后一次性粘贴。
3. 不得只交 `guide.json` 或只交正式成果。
4. 资料不足时仍须写完目录骨架、缺口和待标定指标，并在质量报告中说明断点。
5. 公开回复报告：任务文件夹、课题数、唯一资料数、缺失项。
