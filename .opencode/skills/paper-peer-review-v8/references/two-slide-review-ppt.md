# Two-slide PPT deliverable after peer review

Use this protocol after the scientific review and principle-level reproduction are complete. It integrates the bundled `integrations/two-slide-paper-ppt-codegen` workflow into the review Skill.

## Purpose

For every reviewed manuscript, produce a two-slide editable PPTX that summarizes:

1. **Slide 1 — Method and principle:** the paper's core method, computation/control/optimization logic, and key formulas or algorithm flow.
2. **Slide 2 — Reproduction-informed results:** the most important evidence from the review's principle-level reproduction and, when needed, the paper's own reported result context.

The PPT is not a substitute for the Word review. It is a visual audit artifact that helps the user understand the reviewed paper's method and the reviewer-side reproduction findings.

## Required source skill

Use the bundled two-slide codegen Skill located at:

```text
integrations/two-slide-paper-ppt-codegen/
```

Follow its `SKILL.md`, `references/two-slide-spec.md`, chart styling guide, formula workflow, and QA scripts. Do not flatten the whole deck into images. Use editable text, shapes, connectors, native charts/tables, and replaceable formula SVGs when formulas are used.

## Category mapping

Map the review paper category to a PPT generation route:

| Review category | PPT route | Slide 1 focus | Slide 2 focus |
|---|---|---|---|
| `data_science` | `data_science` / forecasting-style when time-series prediction | data pipeline, preprocessing, model architecture, training/inference distinction | reproduction data chart, time/data generalization, parameter sensitivity, barriers |
| `optimization_planning_operation` | planning-style | objective, decision variables, constraints, uncertainty/scenarios, ESOPT/model-solver loop | ESOPT or reduced-principle reproduction outputs: objective trend, feasibility, cost/risk tradeoff, solver status |
| `system_stability_control` | control/stability-style | dynamic model, controller, feedback paths, stability criterion, Modelica reconstruction | Modelica/principle simulation results: response curves, eigenvalue/damping/stability indicators, robustness or missing-parameter barriers |

When the manuscript is mixed-category, use the primary category route and include secondary-category evidence only when it affects the central claim.

## Result data rule

Slide 2 data visualizations must use **reviewer-side principle-reproduction data** whenever such data were generated.

Acceptable reproduction data include:

- local/public/benchmark/simulated data used for data-science reproduction;
- ESOPT reduced-case variables/objective/constraint status/sensitivity data;
- Modelica/OpenModelica or equivalent dynamic reconstruction traces/eigenvalue/stability data;
- tables generated by reviewer-side parameter or scenario scans;
- partial reproduction outputs that expose why the method cannot be fully reconstructed.

Do **not** redraw the authors' original numerical result and present it as reviewer-reproduced data. If original paper data are shown for context, label that status in speaker notes and the evidence ledger, not necessarily on the visible slide.

If principle-level reproduction could not produce meaningful numerical data because the manuscript lacks critical information, Slide 2 must not fabricate charts. Instead use a compact table/metrics module showing:

- what was attempted;
- what data/model was used;
- where the reconstruction stopped;
- which missing variables, parameters, code, or data blocked a meaningful reproduction;
- what minimum information the authors must provide.

## Required PPT artifacts per paper

For each paper create and retain in the working directory:

- `two-slide-spec.json` following the bundled two-slide spec;
- `evidence-ledger.json` with source-page and reproduction-output references;
- `source-index.json` mapping manuscript evidence, reproduction outputs, and chart data;
- one category-specific logic file:
  - `method-graph.json` for data-science / forecasting-style papers when graph validation applies;
  - `planning-model.md` for optimization/planning/operation papers;
  - `control-model.md` for stability/control papers;
- chart data files produced from reproduction outputs, preferably CSV/JSON, never hand-entered untraceable values;
- final editable PPTX.

Do not place these intermediate files in the final ZIP unless the user asks. The final ZIP should contain the PPTX only.

## Slide content contract

### Slide 1: method / principle

Include:

- paper-specific method title;
- two-line summary of the core idea;
- evidence-grounded method diagram:
  - data-science: input → preprocessing → model → loss/training → output;
  - optimization: objective/decisions/constraints → solver/decomposition → plan/dispatch decision;
  - stability/control: plant/model → controller → feedback → stability/response criterion;
- key formula(s) only when they are essential to understanding the method;
- no visible source citations, review notes, or production notes.

### Slide 2: reproduction-informed results

Use exactly three thematic modules when feasible. Select the strongest three from:

- reconstructed mechanism result;
- sensitivity/parameter scan;
- generalization test;
- ESOPT feasibility/objective/constraint behavior;
- Modelica time-domain or eigenvalue result;
- comparison between paper claim and principle reproduction trend;
- reproduction barrier summary when numerical reproduction is blocked.

At least one module should directly show reviewer-side reproduction data when any exist.

Charts must use reproduction-output data files. Keep chart axes, units, categories, and legends readable. Follow `integrations/two-slide-paper-ppt-codegen/references/result-chart-style.md` for chart styling.

## Evidence boundaries

- Every slide claim must resolve to either manuscript evidence or reviewer-side reproduction output.
- Reproduction charts must identify the data source and generation script in `evidence-ledger.json`.
- Do not claim exact replication unless the same data/code were actually executed.
- A reduced-case ESOPT or simplified Modelica reproduction must be labeled in notes as principle-level validation.
- If a chart is based on simulated data, the simulation rule and parameters must be recorded.

## Final ZIP placement

Each paper review folder must include a `Two-Slide PPT/` folder:

```text
审稿意见/<论文正式题目>审稿意见/
  ...review docx files...
  Latest Relevant Literature/
  Two-Slide PPT/
    <论文正式题目>_Two-Slide_Review.pptx
```

For English papers, the default PPT may be Chinese if the user's workflow is Chinese; generate an English PPT only when explicitly requested or when the project setting requires English slides. If both are generated, use:

```text
<Paper Title>_Two-Slide_English.pptx
<Paper Title>_Two-Slide_中文.pptx
```

## QA gate

Before packaging:

1. Verify the PPTX opens and contains exactly two slides.
2. Render or inspect both slides at full size.
3. Fix overlaps, clipping, unreadable text, hidden legends, missing equations, and broken connectors.
4. Confirm that charts/tables/text/shapes remain editable.
5. Confirm slide 2 charts use reproduction-output data, or that the barrier table is used when no data can be responsibly produced.
6. Confirm the PPTX is present in the paper's `Two-Slide PPT/` folder.
