## 修改代码时看哪里

- `src/app`、`src/components`：页面和交互，原始 TypeScript / TSX。
- `server/recovered/api/src/app/api`：生产 API 的重建实现。
- `server/recovered/api/src/lib`：API 使用的生产业务逻辑。
- `server/recovered/worker/src/lib`：Worker 使用的生产业务逻辑。
- `server/api/index.ts`、`server/worker/index.ts`：源码运行入口。
- `scripts/llm-gateway*.mjs`：模型网关。
- `tools`、`.opencode`：计算和文档工具、Agent 插件及技能。

重建后端保留了编译时的初始化结构和部分重命名符号，以确保行为可验证。两个进程的同名模块可能因为裁剪不同而各有一份；修改共享业务逻辑时需同步相关副本。不能把这些重建 JavaScript 文件冒充原作者完整的 TypeScript 原稿。

## 本地运行

在项目根目录运行：

```powershell
npm ci
npm run dev:local
```

打开 `http://127.0.0.1:3000`。Web、API、独立本地 PostgreSQL 分别使用 3000、4000、55433 端口；请保证这些端口可用。Ctrl+C 会关闭本命令创建的进程，保留本地数据。

全新克隆时，该模式在 `storage/local-development` 内创建空数据库和随机凭据；初始管理员账号为 admin，初始密码记录在同目录 credentials.json。该目录受 Git 忽略。Windows PostgreSQL 原生文件缓存到 `%LOCALAPPDATA%/ai4es-dev-runtime`，避免中文安装路径的编码问题；如缓存根目录含非 ASCII 字符，可通过 `AI4ES_LOCAL_RUNTIME_ROOT` 指定 ASCII 路径。

当前恢复电脑已经导入服务器的最新数据库快照与语料，启动命令根据忽略上传的 `storage/local-development/runtime.json` 使用这些本地数据。数据位置、核验结果及备份说明见 [本地数据导入记录](本地数据导入说明.md)。Git 仓库只包含源码与说明，克隆到其他电脑时需要另行恢复数据。

若要连接自己另行配置的 PostgreSQL，填写 `.env.local` 后分别运行 `npm run api:dev`、`npm run worker:dev`、`npm run dev`。生产数据库请自行使用受控的独立环境，当前重建与测试没有连接线上数据库。
