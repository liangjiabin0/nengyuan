## 1. 用户最终如何使用

### 1.1 新建任务与真实数据

进入“虚拟仿真 → 电力分析”，先选择能力组和实验类型。新建任务按实际数据使用，不自动套用示例算例。

“数据来源”使用下拉选择填写数据或模型文件。“导入计算模型”是上传区域的文字标题，真正打开文件选择窗口的入口为下方“选择文件”；加载示例仍为独立操作。

| 操作 | 用户需要提供什么 | 实际行为 |
|---|---|---|
| 规划与调度 → 填写数据 | 开始日期、时段长度、负荷、电价、供电上限，以及所选任务需要的设备参数 | 由用户数据建立单节点有功模型；不限制为 24 小时。负荷、电价可直接从 Excel 复制一列粘贴 |
| 规划与调度 → 导入计算模型 | 已有 PyPSA NetCDF `.nc` 网络 | 使用原文件中的网络、设备、约束、时间序列和权重，不用页面示例参数覆盖 |
| 静态电网分析 → 导入计算模型 | 已验证的 MATPOWER、RAW、JSON 或网络字段模板 CSV/Excel | 识别、转换、诊断，再允许选择该模型支持的分析 |
| 动态稳定 → 导入计算模型 | 含有效动态设备的 ANDES XLSX，或 RAW + DYR 配对 | 校验动态模型完整性；静态数据不能代替动态参数 |
| 加载示例 | 主动点击示例入口 | 加载 IEEE、园区储能或 Kundur 测试算例，界面和结果保持“示例”标识 |

“填写数据”初始负荷、电价、储能容量、储能功率和购电上限为空。效率、SOC 和时间步长提供可见、可修改的初始设置。删除数值会成为缺失输入，不会被转换成零。切换填写、导入与示例时保留当前页面已输入的内容；刷新恢复当前草稿。

经济调度、机组组合不要求填写无关的储能参数。光伏、风电容量大于零时，要求对应出力系数与负荷时段对齐。新增容量及设备成本必须由用户提供，不能偷偷套用示例成本。

普通用户不需要选择 MCP 或启动方式。“高级设置”显示本任务实际计算引擎和可选计算时限。当前每项新增分析仅有一个已接入主引擎，界面不显示具有误导性的“系统推荐”或不可用切换器。以后验收替代引擎后再开放实际可切换选项。

### 1.2 检查、计算和结果

1. 填写数据或导入模型。导入后展示组件数量、单位、可执行分析及转换警告。
2. 导入模型、选择已有模型或修改参数后自动检查。停止输入约 400 毫秒后请求后台预检查；修改输入会撤销旧检查请求，旧响应不能放行新输入。缺失、越界、时段不一致、动态模型缺失或不支持的分析会被拦截。检查本身不创建计算任务。
3. 检查通过后直接点击“开始计算”，无需手动校验。需要确认的转换警告仍需用户阅读并确认。后台保存输入快照、排队、执行；页面右上角任务卡片显示进度。
4. 结果分别显示求解状态和业务判据。计算成功但电压越限，必须显示越限；不可行、不收敛、取消和失败不显示伪成功曲线。
5. 查看指标、曲线、表格和告警；完整数据可分页或下载。输入、实际引擎、版本、求解器、运行时间、模型口径和输入哈希随结果保存。
6. 结果页的“调整参数”复用该次输入并建立新运行；“新建计算”打开相同分析类型的空白任务。已经处于新建表单时不显示重复的“新建计算”按钮。旧结果保持可读。

页面首屏集中显示任务状态、关键指标和一张主图；全部曲线通过下拉切换，储能任务优先展示 SOC。数据表、输入、运行记录和产物分别按需查看，完整输入与来源说明可展开。导入和诊断在空间足够时并排显示；高级参数折叠，参数列数随可用宽度调整。虚拟仿真复用左侧任务列表，不再重复显示历史下拉框。

### 1.4 多文件的业务边界

每批最多 10 个文件、5 个独立算例，每个文件须非空且不超过 5 MB。静态模型、PyPSA NetCDF 和完整 ANDES XLSX 各自作为独立算例；一个 RAW 必须配套一个 DYR，两者算一个算例。只有一对 RAW/DYR 时允许不同主名；多对同时选择必须按相同主名明确配对，避免猜错网络。不能把多个电网自动拼成一张网络，也不能把任意时序 CSV 自动当作设备数据补入模型。

导入按算例逐个执行，逐项显示排队、检查、成功或失败。右上角 × 可取消本批或清空当前选择，每项 × 可取消/移除该项；同一个文件可以重新选择上传。取消会中断上传请求，后端通过请求中断信号停止导入诊断子进程并清理本次新建目录。导入已完成后移除选择不会删除历史模型或计算结果。

失败项不会被默默跳过。用户可移除失败项再计算，其余已成功文件保留。全部选中算例自动预检查通过后，点击“开始计算（N 个算例）”，同批按事务整体创建任务和既有队列记录。权限、容量、关联或参数检查失败会整体回滚；相同请求编号重试不重复建任务。当前账号最多保留 5 个待执行任务，超出时明确提示等待。批量计算沿用每个算例自己的 RunSpec/ResultBundle、目录、权限和结果，不新增并行协议。

填写的真实数据使用 `custom-timeseries` 模型标识，输入及结果来源为 `user`；上传模型来源同样为 `user`。主动加载的算例使用原示例标识和 `sample`。来源会参与模型身份及结果一致性检查，历史示例不会被改标成用户数据。

### 1.3 刷新、离开与长计算

浏览器刷新、切页或关闭不会取消后台计算。再次进入恢复同一运行编号；已完成时显示已保存结果。URL、按账号隔离的页面记录和服务端历史共同恢复任务、栏目和当前草稿。重复提交同一 requestKey 和相同输入只生成一个任务；同一编号配不同输入返回冲突。

默认计算时限为 0，即不限制累计求解时长。pandapower 的 10 分钟、PyPSA/ANDES 的 2 小时为运行提醒，不是自动终止时限。用户在高级设置主动填写时限，或管理员明确配置硬上限后才按该时限结束任务。MCP 连接与工具发现有独立保护，不能把其限时套到正常数值求解上。

服务器或 Worker 停止与浏览器刷新不同：当前没有数值求解器内存断点续算。运行中进程中断会保留诊断，不能假装继续或自动重跑。已完成结果重启后仍可恢复。部署前检查活动任务并等待结束。

## 2. 原有功能保留

方案求解继续使用 `SchemeSolveWorkbench`、`SchemeFlowCanvas` 和 `SchemeNodeInspector`。保留历史、搜索、新方案、附件、12 个起点、头脑风暴、多分支、不可研究原因、逐分支设计求解、共享审查、报告及导出。原有画布平移、缩放、适应视图、缩略图和节点选择继续存在；新增计算不能用聊天面板替换画布。

设计节点增加受控计算入口，关联方案和分支。关联不代表已经把自然语言方案转换为电网算例，必须确认实际输入。MGPlan 专用编辑、结果、文档、过程和对比继续走原面板。原 ESOPT、Dispatch、TDMG/PYPOWER、Modelica、线损和预测入口保留。

虚拟仿真的原 11 类实验继续存在：光伏、风电、负荷、电量预测，优化调度、交流最优潮流、理论线损、Modelica、DCOPF、LP、MIP。能元 Agent、方案求解和虚拟仿真沿用各自入口并共享新计算服务，不新增一级导航。

对话模型继续复用 Arc / Thunder / Storm 的公共配置与权限。对话模型用于理解和解释；电力模型是具体网络、设备与时序，两者不能混为同一选择项。

任务卡片为右上角小浮层，开合不改变画布或对话宽度。侧栏底部“修改密码”“账号管理”在一行左右排列；用户名旁的状态绿点和该点专用轮询移除。账号管理仍仅向管理员展示。

## 3. 任务与真实引擎对应

| 能力组 | 已接入任务 | 执行方式 | 主要输出 |
|---|---|---|---|
| 静态电网分析 | AC/DC 潮流、AC/DC OPF、N-1、N-2 | pandapower 原生主链；受控 MCP 可调用相同适配器 | 收敛、电压或相角、负载、网损、越限、故障场景 |
| 规划与调度 | 储能联合调度、经济调度、机组组合、容量扩展 | PyPSA + HiGHS，经专用 MCP | 成本、出力、SOC、弃电、新增容量和成本构成 |
| 动态稳定 | 故障时域、小信号稳定 | ANDES，经专用 MCP | 电压、功角、转速、可用频率测量；特征值、阻尼、模态和参与因子 |
| 原通用物理仿真、线损、优化及预测 | 原实验目录 | 原 Backend / 专用流程 | 原有结果及产物 |

ANDES 潮流仅用于动态初始化，不额外建设重复潮流入口。直流近似不报告未经计算的交流电压或网损。模型未包含频率测量时不生成母线频率曲线，发电机转速不能直接冒充母线频率。

## 4. PowerIO 和 MCP 如何使用

浏览器只调用能元任务 API。PowerIO 是共享导入与转换层，不要求普通用户操作 PowerIO/MCP。文件由独立导入目录识别，保留原文件、转换模型、哈希、单位、数量、警告和不支持项；导入产物随运行复制保存。

Worker 根据 `tools/power-mcp/capabilities.json` 选择已验收能力，按 `servers.json` 的工具允许列表启动独立进程。每个运行有自己的目录和模型状态，允许根目录仅指向该任务。原 OpenCode/ESOPT 配置和门禁继续使用；新计算不借用 ESOPT 解锁标记。

| 服务 | 当前真实调用链 | 说明 |
|---|---|---|
| pandapower | 直接 Backend 调用 `static_analysis`；MCP 路径调用 `run_static_analysis` | 共用数值实现，避免两套校核逻辑 |
| PyPSA | `run_planning_analysis` | 根据已填数据建立网络，或保留上传的原生网络；HiGHS 求解后导出实际网络和完整时序 |
| ANDES | `run_power_flow` → `run_time_domain_simulation` / `run_small_signal_analysis` | 先验证初始化和动态设备，再执行时域或小信号分析 |
| PowerIO | 导入适配器调用原生格式解析/转换；真实 MCP 解析和根目录限制亦有测试 | 不承诺任意版本文件均能无损互转，以诊断为准 |

MCP 执行先 initialize 和 tools/list，再核对允许工具并发送结构化参数。原始工具请求响应仅保存为受权限保护的诊断产物；普通页面显示已执行步骤摘要，不展示模型内部思考链或服务器路径。没有修改第三方安装包源码。

冻结环境：Python 3.12、PowerMCP 0.4.0、PowerIO 0.11.5、pandapower 3.5.6、PyPSA 1.2.4、ANDES 2.0.0、HiGHS/highspy 1.15.1；完整依赖在 `tools/power-mcp/requirements.lock.txt`。升级必须重跑真实算例与独立数值对照。

## 5. 项目结构与统一协议

持久化输入使用现有 `RunSpec/1.1`，结果使用 `ResultBundle/1.1`。`specView` / `resultView` 只用于兼容既有页面和旧记录，不另存一套平行协议。

| 模块 | 职责 |
|---|---|
| `src/lib/power-compute/catalog.ts`、`input-form.ts` | 能力及示例目录；生产空白表单、显示字段和粘贴数据处理 |
| `schema.ts`、`contracts.ts` | 严格输入、单位和边界检查，哈希与结果一致性，统一协议 |
| `models.ts`、`imports.ts` | 用户模型归属、原始文件、格式诊断和导入清理 |
| `store.ts`、`runner.ts`、`timeouts.ts` | 事务、幂等、现有后台队列、进程控制、租约、终态保护 |
| `public-view.ts`、`health.ts` | 输出脱敏、角色检查所需公共结果、组件健康检查 |
| `power-compute-panel.tsx`、`power-result-details.tsx`、`power-task-indicator.tsx` | 参数确认、历史恢复、结果展示、表格分页和浮层进度 |
| `tools/power-mcp/analysis.py`、`native_planning.py`、`execute.py`、`server.py` | 原生数学模型、导入网络求解、MCP 适配与产物 |
| `diagnose.py`、`tabular.py`、`import_limits.py` | 共享导入诊断、网络表格模板、压缩与文件安全边界 |

实际 API：

- `GET/POST /api/power-runs`：历史与创建；`POST ?check=1` 只检查，不入队。
- `GET /api/power-runs/{id}`、`POST /api/power-runs/{id}/cancel`：状态及取消。
- `/api/power-runs/{id}/tables/{tableId}`、`/artifacts/{artifactId}`：分页数据、下载。
- `GET/POST /api/power-models`：已导入模型和文件导入；GET 模板参数提供静态 JSON/CSV 字段模板。
- `/api/power-capabilities`：当前能力可用性；`/api/system/power-engines`：管理员组件状态。

成功结果必须包含实际 `engine/version/solver/source/fidelity`、输入哈希和执行时间。统一产物为输入、ResultBundle、原模型、结果表格、图表及日志。导入模型的权重、币种和约束不能被单节点示例假设覆盖。

## 6. 正确性、权限和运行边界

- 严格拒绝未知参数、非有限数、错配引擎与模型、无权限模型、无效日期和错位时序。用户模式缺少关键设备或成本参数时不得靠示例默认值补齐。
- PyPSA 输入支持 2—8760 个等长时段；负电价允许，负负荷拒绝。SOC 范围、初末状态、功率平衡和费用构成独立校验。零成本问题不添加伪造微小价格；零/负电价和无损储能启用充放电互斥约束。
- 填写方式为单节点有功模型，不模拟线路、交流电压、电池衰减或全系统稳定。需要这些约束时使用相应模型与任务，不能夸大结果范围。
- 原生 PyPSA 支持当前已验收的单投资期网络；最多 500 母线和受限设备/时间点数量。多投资期、更大型模型需要扩展 Schema 和专项验收。
- N-1/N-2 支持线路、变压器和明确设备集合；限制最多 5000 种组合，孤岛、不收敛和越限分别记录。任意拓扑的全面安全性不由一个成功基础潮流替代。
- 动态分析时间上限 600 秒、步长 0.005—0.05 秒、名义时间点预算 120000，并检查输出通道预算。电压恢复判据只评价选定母线和窗口。
- 上传单文件最多 5 MB，multipart 总体 10 MB，JSON 请求 2 MB。Excel/CSV 必须符合声明的网络字段，不能把任意电子表格当成电网模型。检查稀疏超大表、压缩膨胀、公式、外部链接和 HDF5 外部数据引用。
- 每次下载、分页、取消和读取都检查任务归属。普通用户无权读取原始内部调用记录；管理员权限也不能绕过其他任务归属。前端响应隐藏服务器绝对路径和敏感字段。
- 取消传播到该任务子进程；晚到结果不得覆盖取消。导入失败只清理本次新建目录。错误结果不填零冒充正常数据。
